# T-278: key map V2 keys typed-space floor lines once into FLOOR.INTERNAL

Lane I tooling. No engine quantity, rule, method or registry file changes; the key map only decides which reference
row a candidate line answers.

## Physical element and the defect

FLOOR.INTERNAL is the internal floor area (the freelancer's floor cover row FIN:الغلاف:15, 409.58 m2). In
ARCH_TAKEOFF_V3.0.14 the internal floor line is, by the engine's own definition (engine/source/arch_v3014.py
`floor_line`), the live FIN.FLOOR.PORCELAIN + FIN.FLOOR.WET_TILE lines **plus** the live ARCH.SPACE lines the engine typed
`floor_scope_v3014.floor_key = FLOOR.INTERNAL`. Key map V1 (T001B) keys by item code only and by rule never keys
ARCH.SPACE (an untyped space line is a geometry record that restates measured surfaces). So the two typed space lines
were scored nowhere: the 1F dressing (ENTER_FLOOR, 1.65 x 1.80 = 2.970 m2) and the 1F arrival landing split out of the
settled living range (SETTLE_RANGE SPLIT_OUT, 4.9225 m2). A scoring-key gap, not a quantity defect.

## Change

- `tools/alsenan_keymap.py`: new opt-in path "T-278: typed lines" for a key map with SCHEMA URBAN_ALSENAN_KEY_MAP_V2:
  a key may name `typed_lines` selectors {item_code, field, equals, source} read from the type records the map lists
  (`typed_records`); a line is keyed by what it IS. Refused: a selector code that is also a plain item code, a line two
  keys claim, type records that disagree, a selector without its source, a V2 map without typed records. A typed line no
  selector names stays UNMAPPED. `adapter.coverage` lists, per item code and unit over every line (exclusions counted
  apart), the lines keyed (plain / typed, by key), unkeyed (by typed value) and double-keyed (always 0). Any V1 map
  takes none of this path.
- `tests/alsenan/T001C_KEY_MAP.json`: T001B key for key (same reference ids, same item codes) plus one selector on
  FLOOR.INTERNAL: ARCH.SPACE with floor_key FLOOR.INTERNAL. T001B is untouched.
- `tests/t278_keymap_typed_lines/`: synthetic villa (not Alsenan), hand calculation in the module docstring; adverse
  cases: held typed line (key HELD, never a partial sum), missing quantity (HELD, never 0), mm unit (refused, never
  converted), NOT_APPLICABLE (excluded), selector code also a plain code, two keys on one line, records disagreeing,
  missing source / records, mirror / order change, the V1 path ignoring type records, the run path.

prefix; a line in two keys is refused, a line in none is listed. Scope: every scoreboard key map from V2. Provenance:
