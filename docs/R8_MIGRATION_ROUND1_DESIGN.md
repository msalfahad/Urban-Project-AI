## 1. Why this round, and only this round

The R8.5 value shadow found exactly one row class where the canonical path reproduces the published
value from the current inputs, by the current method. These are the Qortuba FINAL rows whose value is a
plain sum of room floor-polygon areas:

| row | rooms | published | canonical (preview) |
|---|---|---|---|
| Q-03 wet-area waterproofing, floor | 3 × BATH | 17.8625 m² | 17.8625 (Δ 3.7e-11) |
| Q-03P pantry waterproofing, floor | PAINTRY | 11.685 m² | 11.685 (Δ 1.0e-13) |
| Q-11 ceramic floor, wet rooms | 3 × BATH | 17.8625 m² | 17.8625 (Δ 3.7e-11) |
| Q-12 ceramic floor, service room | PAINTRY | 11.685 m² | 11.685 (Δ 1.0e-13) |
| Q-13 porcelain floor, dry rooms | HALL, M.B.ROOM, 2 × BED.ROOM, DRESS, unlabelled | 108.9625 m² | 108.9625 (Δ 8.6e-11) |
| Q-14 ceiling by area | all 10 rooms | 138.51 m² | 138.51 (Δ 4.9e-11) |

That is 10 rooms, 101 source observations, and a maximum canonical edge residual of 0.01745 mm.

Excluded, and staying on the active path: 15 VALUE_METHOD_NOT_MIGRATED (wall, opening and perimeter
methods), 6 VALUE_NOT_COMPUTABLE and 1 VALUE_TRADE_RULE_UNDECIDED. The round also excludes:

- the room perimeter quantities;
- every P7757 and Al Rashed value;
- `cad_adapter`;
- every R9 trade rule.

The round changes **where the geometry comes from**. It does not change any rule applied to it. The
rules already applied to these rows stay exactly as approved: US-01, US-04, US-14, US-15, QP-07, QP-13,
QP-14, QP-15 and M. This holds by construction. A round that would change a published number is not
this round, and it aborts (§4).

## 3. Required capability signatures (G4)

The 101 observations exercise 10 of the source's 33 signatures. Every observation has a signature.

| observations | signature |
|---|---|
| 86 | `KIND=LINE\|CHAIN=DEFAULT_FRAME\|NET=NET_DIRECT\|DEPTH=0\|…\|HANDLE=H12` |
| 10 | `KIND=LWPOLYLINE_STRAIGHT\|CHAIN=DEFAULT_FRAME\|NET=NET_DIRECT\|DEPTH=0\|…` |
| 1 | `KIND=LWPOLYLINE_BULGE\|CHAIN=DEFAULT_FRAME\|NET=NET_DIRECT\|DEPTH=0\|…` |
| 3 + 1 + 3 | LINE at depth 1, NET_REFLECTED (reflection with rotation, scale or translation) |
| 3 + 1 + 3 + 1 | LINE at depth 1, NET_DIRECT (rotation, scale or translation) |

The signature columns are in the register. Two consequences follow:

- **Instance coverage.** 15 of the observations sit inside block instances, 7 of them net-reflected. A
  qualification that exercised only model-space lines would not cover this round.
- **Handle-keyed comparison.** The comparison is per handle, so the export's HANDLE_IDENTITY must be
  VERIFIED. If an export does not preserve handles, no geometry-keyed substitute exists today
  (EQUIVALENCE_RULES = ()), and G4 stays unmet. Adding one would be a separate, reviewed change.

## 4. Execution design (when, and only when, G1–G7 hold)

1. **Freeze inputs.** Record:
   - source sha256;
   - decoder build sha256;
   - qualification id;
   - unit claim id;
   - designation id;
   - frame id;
   - evidence version;
   - the published row versions being superseded.
2. **Dual run.** Compute each row twice from the same frozen inputs: once on the active path and once
   canonically. Both stay runnable.
3. **Acceptance per row.** Accept a row only if the canonical value, rounded to the published precision,
   equals the published value, and the per-room inputs match one-to-one. Any difference aborts the
   whole round. Nothing is published, and the difference is reported as a finding. There is no partial
   acceptance and no tolerance widening.
4. **Publication by supersession.** Each accepted row gets a new version, the canonical one. Its provenance
   is:
   - quantity ids;
   - geometry ids;
   - observation ids;
   - frame id;
   - evidence version;
   - method id (`URBAN_SHADOW_ROOM_FROM_CANONICAL_EDGES_V1`, promoted under its own id);
   - qualification id.

   A supersession record links the new version to the previous one. The previous version is never
   overwritten or deleted. Published BOQ figures are numerically unchanged, which is the acceptance
   condition. Approved owner answers and benchmark truth are untouched.
5. **Report.** A before/after table, every row identical, with the full provenance chain.

## 5. Rollback

- The active path is not removed or modified in this round. It stays runnable and it is the comparison
  in step 2.
- Rollback is a further supersession back to the previous row version, with a reason and an author. It
  is never a deletion, and never a silent switch.
- Each row carries its own source flag. Rolling back one row does not touch the others.
- A rollback trigger is any later finding against the frozen inputs:
  - the unit claim is superseded;
  - the designation is rejected;
  - the qualification is withdrawn;
  - a V-CAD-5 regression on the row region.
