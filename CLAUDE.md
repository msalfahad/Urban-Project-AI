# Urban-Project-AI: agent guide

Kuwait BOQ / quantity takeoff engine: DWG/DXF/PDF plans in, traceable BOQ out. Python 3.11, ezdxf 1.4.4, shapely 2.2.0.
Working branch: `claude/access-permissions-setup-ii24ws` (`main` holds only a README).

## Find things first (do not explore the tree)

- `docs/ROUTING.md` (start here): per task topic (CAD, units, rooms, walls, doors, windows, finishes, waterproofing, stairs,
  concrete, rebar, formwork, excavation, BOQ output): the modules to open first, their rules, tests, dependencies, how widely
  each module is imported (SHARED = wider tests), and the known defects with their status and original evidence.
- `docs/CODEMAP.md`: every module with its line count and purpose; big modules list their public symbols with line numbers.
- `docs/RULES_INDEX.md`: every rule, which file stores it, which code applies it and which test proves it.
- All three are generated by `python3 -I tools/codemap.py` (`--check` says whether they are stale). The only hand-kept input
  is `tools/routing_topics.json` (topic patterns and the list of defect registers). After adding, moving or renaming files,
  adding a rule version or writing a new defect register, update that list if needed and regenerate in the same commit.

Open the one file the map points to, Grep inside it for the symbol, then Read only that range (about 80 lines).
Never read a module over 1,500 lines whole, and never read `research/` unless the task is about a report.

## Size the task, then match the effort

- **Small** (one value, one function, one rule record, one bug): locate with the maps, edit, run the one test file for that area.
  Minutes, not hours.
- **Medium** (new field, new rule version, method tweak): the test folder for that area (`tests/m9_<phase>/`, `tests/m9_kb/`).
- **Large** (new method version, new pipeline stage): 5-line plan first; full suite once at the end, in the background.
- Do not run the full suite, a clean-clone re-run or `freeze_verify.py rebuild` for small or medium tasks, unless a changed
  module is SHARED or touches geometry, units, BOQ lines or the release model (see `docs/ROUTING.md`). Test selection is your
  judgement; nothing is skipped automatically.
- Do not write reports, proofs, packages or registers unless the prompt asks for them. Finish with 3-5 lines:
  what changed (file:line), how it was checked, what was not done.

## Never break (fast does not mean unsafe)

- Frozen methods (ARCH_TAKEOFF_V1 ... released versions), frozen baselines and existing rule/knowledge version files are never
  edited in place. A behaviour change is a new method or rule version.
- After any change under `engine/`, `tools/`, `rules/`, `knowledge/` or `data/registry/`, run the read-only freeze check:
  `PYTHONDONTWRITEBYTECODE=1 python3 -I tools/freeze_verify.py check --index research/freeze_integrity/FREEZE_BASELINE_INDEX.jsonl`
  Expected `frozen artefacts differing from the index: 0`. A difference means stop and report.
- The root `conftest.py` fails a session that changes `data/` or `tests/` files; tests must not write there.

```
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -p no:cacheprovider -q tests/<folder or file>   # targeted tests

```
